# 電子ペーパーケース書き込みアプリ（非公式）

エレコムの電子ペーパー付き iPhone ケース（PM-A24AEINK01 / PM-A25AEINK01、480×800・赤黄白黒の4色）の
背面画像を、公式アプリが対応していない iPhone（iPhone Duo など）から NFC で書き換えるための iOS アプリです。

> **重要: 実機では未検証です。**
> このケースの通信方式は公開されていません。同じ系統とみられる NFC 電子ペーパー基板（FMSC 系）の
> 公開解析情報をもとに実装しており、手元にケースが無い環境で作ったため、**このケースで動くかどうかは
> まだ確認できていません**。最初は下の「はじめて使うとき」の順に、読み取りだけの操作から試してください。

## できること

- 写真を選び、位置・大きさ・明るさ・コントラスト・あざやかさを調整して4色に変換（仕上がりをプレビュー）
- NFC でケースに転送して画面を書き換え
- 向き合わせ用のテスト画像の書き込み、白で消去、再描画のみ
- ケース情報の読み取り（書き込みを一切しない診断）と通信ログのコピー

## 必要なもの

| 必要なもの | 補足 |
|---|---|
| Mac と Xcode 16 以降 | iOS アプリのビルドと iPhone へのインストールに必要 |
| **有料の Apple Developer Program**（年額） | NFC タグ読み取りの権限は無料の Apple ID では使えません |
| iOS 17 以降の iPhone | NFC 搭載機 |

## インストール手順

1. Mac でこのリポジトリを取得し、`EPaperCase.xcodeproj` を Xcode で開く
2. ターゲット **EPaperCase** → **Signing & Capabilities** で
   - **Team** に自分の開発者チームを選ぶ
   - **Bundle Identifier** を自分専用の文字列に変える（例: `jp.自分の名前.epapercase`）
   - 「Near Field Communication Tag Reading」が表示されていることを確認する
3. iPhone を Mac につなぎ、実行先に選んで ▶ を押す

## はじめて使うとき

ケースは iPhone 16 用なので iPhone Duo には装着できません。**ケースの内側（本来スマホを入れる面）を、
スマホ背面の上部に重ねて**ください。画面（電子ペーパー）が外側を向き、描き換わる様子が見える向きです。
画面側をスマホに当てると電力が十分に伝わりません。机に置いて重ね、通信が終わるまで動かさないでください。

1. 左上のメニュー →「**ケースの情報を読み取る**」
   読み取りだけを行います。「480×800 4色」のように表示されれば、想定どおりの方式です。
2. メニュー →「**テスト画像を書き込む**」
   左上が黒・右上が赤・左下が黄で「上 TOP」が読めれば成功です。
   - 鏡文字・上下逆 → 設定の「左右を反転」「上下を反転」を切り替える
   - 縞模様・砂嵐 → 設定の「データの並び」を切り替える
3. 「写真を選ぶ」→ 調整 →「**ケースに書き込む**」

転送に十数秒〜数十秒、その後の画面更新に20〜30秒ほどかかります。iOS の制限（タグとの接続は約20秒、
読み取りシートは60秒まで）を越えないよう、途中で自動的につなぎ直したり、読み取りシートを開き直したりします。
途中で失敗したときは「続きから再開」を押すと、転送済みの部分を飛ばして再開します。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 読み取りシートが出たまま何も起きない | 当てる位置を変える。それでも検出されない場合、このケースが想定と違う方式で、iOS がタグを渡してくれていません |
| 「想定と異なる通信方式のようです」 | このアプリの方式では書き込めません。設定 → 通信ログ をコピーして控えてください |
| 「電力不足」 | 位置が合っていません。ケースとスマホを密着させ、位置をずらして再試行 |
| 「PIN認証が必要」 | 設定 → 認証。誤った PIN の連続送信はロックの原因になり得るため慎重に |
| 画面更新の途中で止まり、表示が乱れた | メニュー →「再描画だけ行う」 |

設定 → 通信ログ に、ケースとのやり取りがすべて残ります。動かなかった場合はこのログが原因調査の手がかりになります。

## しくみ

通信は ISO 14443-4 (ISO-DEP) 上の APDU です。

| コマンド | 用途 |
|---|---|
| `00 D1 00 00 00` | 基板情報 (TLV) の読み出し。パネルの画素数・色数・スキャン方向をここから判定 |
| `F0 D8 …` | アクセス権の確認 |
| `F0 D3 slot last len block sub + データ` | 画像を2000バイトごとに LZO1X 圧縮し、250バイトずつ送信 |
| `F0 D4 85 00 00` | 保存済みの画像で画面を更新（完了まで応答を保留） |
| `F0 DE 00 00 01` | 描画中かどうかの確認 |

画素は 1バイトに4画素（2ビットずつ、0=黒 / 1=白 / 2=黄 / 3=赤）で詰めます。

安全のため、基板内のパネル駆動設定を書き換えるコマンド（`DA` / `DB`）は実装していません。
送るのは画像データと「再描画」の指示だけです。

## 開発

```sh
swift test   # Core（プロトコル・圧縮・画像変換）の単体テスト。macOS で実行
```

- `EPaperCase/Core` … UI・NFC に依存しないロジック（`Package.swift` からテスト対象として参照）
- `EPaperCase/NFC` … Core NFC のセッション管理
- `EPaperCase/UI` … SwiftUI の画面

GitHub Actions（`.github/workflows/ci.yml`）で、push のたびに単体テストと署名なしの iOS ビルドを行います。
macOS ランナーを使うため、非公開リポジトリでは Actions の利用時間を消費します。不要ならこのファイルを削除してください。
